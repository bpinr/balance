# Payments

Учебная платёжная система на Go. Данные хранятся в памяти: пользователи с балансом, очередь переводов между ними и конкурентная обработка этой очереди несколькими воркерами.

## Запуск

Нужен Go 1.22 или новее (проект написан на Go 1.27).

```bash
go run ./...
```

Проверка на гонки данных:

```bash
go run -race ./...
```

На Windows для `-race` нужен cgo, то есть компилятор gcc в `PATH` (например, WinLibs или MinGW-w64).

Весь код находится в `internal/model/account.go`.

## Версии

Каждая часть задания лежит в своей ветке.

| Ветка | Что добавлено |
|---|---|
| `v1` | Структура `User` (ID, имя, баланс). Методы `Deposit` и `Withdraw` на `*User`. `Withdraw` возвращает ошибку при нехватке средств, и баланс не уходит в минус. |
| `v2` | `PaymentSystem`: пользователи в мапе и очередь транзакций в слайсе. `AddUser` (отклоняет повторный ID), `AddTransaction`, `ProcessingTransactions` (ищет отправителя и получателя, списывает и зачисляет, запрещает перевод самому себе). `main` обрабатывает очередь в цикле. Тексты ошибок на латинице. |
| `v3` | Конкурентная обработка: буферизованный канал, 3 воркера, `sync.WaitGroup` (`Add` до запуска горутины, `Done` через `defer`), `close(ch)` и затем `wg.Wait()`. Мьютекс на `PaymentSystem`. |
| `v4` | `sync.Mutex` в `User` защищает `Deposit` и `Withdraw`. Мапа хранит `*User`, потому что мьютекс нельзя копировать. `PaymentSystem` защищает мапу через `sync.RWMutex`, поэтому переводы между разными пользователями идут параллельно. |

## Особенности

- **Суммы.** Деньги хранятся в копейках (`int64`), чтобы не терять точность на `float64`. Поле `Transaction.Amount` по условию задания имеет тип `float64` и перед списанием приводится к `int64`.
- **Порядок обработки.** Порядок, в котором воркеры обрабатывают транзакции, не гарантирован. Если перевод зависит от предыдущего (тратит деньги, которые только что пришли), он иногда получит `insufficient funds`. Это нормальное поведение для конкурентной обработки.
